1. Introduction

CyberShield is a beginner-friendly cybersecurity monitoring dashboard built with Python and Streamlit. It demonstrates how login activity data can be collected, analysed, and visualised to detect suspicious behaviour — without connecting to real systems or using machine learning.

The entire project lives in a single file (app.py) and uses only plain Python if statements and standard data manipulation so that any beginner can follow, run, and extend it.

Project goal: Build a functional security dashboard that loads login records, automatically flags suspicious IPs using a threshold rule, displays results with colour-coded charts and tables, and lets the user filter data interactively — all in one Python file.

2. Objectives

  1. Display a live summary of login activity (total, successful, failed, suspicious).
  2. Load and present 20 realistic fictional login records in a colour-coded table.
  3. Automatically detect suspicious IP addresses using a configurable threshold rule.
  4. Show clear, plain-English warning alerts for every flagged IP.
  5. Provide two analytical charts to visualise login patterns at a glance.
  6. Allow the user to filter records by login result and risk level.
  7. Keep the entire project in one readable file suitable for beginners.

5. Features

5.1 Summary Metric Cards

Four cards show Total Logins (blue), Successful Logins (green), Failed Logins (orange), and Suspicious Activities (red). All numbers are calculated live from the data.

5.2 Suspicious IP Detection Rule

# THE RULE — plain Python, no ML SUSPICIOUS_THRESHOLD = 5 for ip_address, fail_count in failed_counts.items(): if fail_count >= SUSPICIOUS_THRESHOLD: suspicious_ips.append(ip_address) # flag this IP

Any IP that fails 5 or more times is flagged. The threshold is a single number — change it to make the rule stricter or looser.

5.3 Risk Level Classification

Risk LevelConditionMeaning
LowLogin succeededNormal user — no action needed
MediumLogin failed, IP not flaggedPossible typo or forgotten password
HighLogin failed AND IP has ≥5 failuresLikely brute-force attack — block IP at firewall

5.4 Warning Alerts

A Streamlit warning banner appears for every suspicious IP showing: the IP address, failure count, usernames attempted, a plain-English explanation, and a recommended action.

5.5 Analytics Charts (Plotly)

  • Login Outcome Comparison — bar chart of Success vs Failed totals. A growing Failed bar signals an attack.
  • Failed Attempts by IP Address — one bar per failing IP. Suspicious IPs are coloured red; normal failures are orange.

5.6 Interactive Filters

  • Filter by Login Result — All / Success / Failed
  • Filter by Risk Level — All / Low / Medium / High

Filters apply sequentially using plain if statements. A caption always shows how many records are visible out of 20.

5.7 Colour-coded Table

Each row is highlighted by risk level: red for High, dark-orange for Medium, green for Low. Row colouring uses the Pandas Styler API.

12. Limitations & Future Work

Current Limitations

  • Data is static and fictional — not connected to a real log source or database.
  • The rule counts total failures only; it does not consider time windows.
  • No user authentication — anyone who can reach the URL sees the dashboard.
  • No persistent storage — data resets on every page refresh.

Possible Future Enhancements

  • Connect to a live log file or SQLite / PostgreSQL database.
  • Add a time-window rule: flag IPs with 5 failures within 60 seconds.
  • Export flagged records to CSV for offline review.
  • Add email or webhook alerts when a suspicious IP is detected.
  • Deploy publicly using Streamlit Community Cloud (free).
  • Add a login page to restrict dashboard access.

13. Conclusion

CyberShield successfully demonstrates the core concepts of a security monitoring dashboard in a compact, beginner-readable Python file. It shows how login data can be structured, how a simple counting rule can detect brute-force patterns, how risk levels can be assigned automatically, and how charts and filters make security data easier to understand.

All 11 test scenarios passed. The suspicious IP was correctly detected and flagged, the dashboard numbers updated automatically, the charts clearly visualised the attack pattern, and the filters responded correctly to every combination of input.

The project proves that meaningful cybersecurity tooling does not require complex algorithms — clear logic, good data structure, and a readable UI are enough to build something genuinely useful as a learning and demonstration tool.
